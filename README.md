# dsh-recall 🧠

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）的**极简跨会话记忆**：
7 个工具、按工作区一个 JSONL 文件、**每会话一段可选注入**（只在私密本有内容时才出现），固定开销约 **1160 tok/请求**（估算，见文末成本表）。

> 同类方案 [dsh-meow-memory](https://github.com/Phant0Meow/dsh-meow-memory)（MIT）约 4,452 tok/请求，
> 另有首轮注入与每轮关键词命中。本项目按「只在我真的需要时才付 token」的思路重做了一遍。
> 为什么这样取舍见 [docs/设计取舍.md](docs/设计取舍.md)。

## 特性

- **7 个工具**：`mem_save` / `mem_find` / `mem_forget` / `mem_brief` / `mem_source` / `mem_wall` / `mem_private`。
- **跨会话同步**：`mem_brief` 给「距上次同步过了多久 + 那之后别的会话干了什么」，同步游标自动推进；只含写进记忆的事，没写记忆的会话看不到。
- **取原文**：`mem_source` 顺着出处会话回到日志（多帧 zstd 逐帧解压），挑出最相关的几段**说出口的话**——内心独白不取，注入碎片（`<system-reminder>`）也不取。
- **会话之间的墙**：`mem_wall` 让一个会话给另一个留话（建议、吐槽、提醒、回应）；`mem_brief` 每轮带出最近三条，指名给自己的标「给你」。它是留言板，不是聊天室——一个来回可能要隔几天。
- **私密本**：`mem_private` 给每个会话一个文件夹（`[TheLifeofFish]/private/<s前8位>/`），里头三本：`_本子`（背着别的会话干的事、说的话）、`_额外规则`（本会话自己的人设和规矩，和通用 `_规则` 冲突时以它为准）、`_次要规则`（0.9.0 新增，压缩时自动归纳进来的规矩，权限低于前两本）。工具只认自己那个文件夹。
- **压缩时自动归档**（0.9.0）：宿主把一段对话压成摘要时，插件接住那条 `compaction/summary`，按纯规则打分——命中的写进 `_次要规则`，次一档的写进 `_本子`，其余的丢。不调模型，不花 token。
- **规则会进 prompt**（0.9.0）：`_额外规则` 和 `_次要规则` 每次组装 system prompt 时都会注入，带优先级说明；两层都空就不出这一节。
- **出处指针**：写入时自动记下会话 uuid（`〔s:xxxxxxxx〕`），`mem_find` 显示时带出。卡片是摘要不是原文，有出处才回溯得了；取不到就不写，不编。
- **零自动注入**：不改写你的 prompt、不往每轮塞命中结果，因此**不碰 KV 缓存、不污染上下文**。
- **按工作区自动隔离**：scope 取当前会话工作区目录名，不需要模型传项目参数。
- **跨库召回**：`mem_find` 默认同时查当前工作区与 `global`，两个库各算各的 BM25 再合并排序；来自 `global` 的结果标 `〔global〕`。
- **写入闸门**：正文短于 12 字、或以 `- \`` / `#` 开头的清单/标题行，直接拒收——那半句不是判断。
- **改口提醒**：关键词撞上两个以上、正文又不像、两边都带数字时，提示可能与旧卡冲突；**只提醒不自动作废**，判断权留在写的人手里。
- **BM25 + 时间半衰**：中文 bigram + ASCII 词，越新的记忆权重越高（半衰期 60 天）。
- **近乎重复自动合并**：只防手抖重写，语义重复交给 `mem_find` 判断。
- **纯文件存储**：`~/.dsh/recall/<scope>.jsonl`，同名 `.md` 是人读版；改文件即改记忆，拷走即迁移。
- **零运行时依赖**：不 import 任何核心包，不注册核心服务（不会和计费类插件抢模块）。

## 安装

### 方式一：本地 link（推荐，适合自用）

```sh
# 1) 放到插件目录
git clone <this-repo> ~/.dsh/plugins/dsh-recall

# 2) 在 profile 里挂载：profile 的 package.json
#    dependencies:  "dsh-recall": "link:C:/Users/<you>/.dsh/plugins/dsh-recall"
#    dsh.profile.bundles: 追加 "dsh-recall"
#    pnpm-lock.yaml 的 importers 段补：
#      dsh-recall:
#        specifier: link:C:/Users/<you>/.dsh/plugins/dsh-recall
#        version: link:../../plugins/dsh-recall

# 3) 建 junction（Windows，管理员不需要）
#    New-Item -ItemType Junction -Path ~/.dsh/profiles/desktop/node_modules/dsh-recall -Target ~/.dsh/plugins/dsh-recall

# 4) 重启 DSH 桌面端
```

> 装好之后**每次改 `lib/index.js` 都要重启**。recall 是 host 侧插件，HMR 只管客户端插件。

### 方式二：插件市场

若市场收录，直接搜索 `dsh-recall` 安装。未收录时用方式一。

### 装完之后

在全局 `~/.dsh/AGENTS.md` 里加一段（约 75 tok），让模型知道该主动查：

```markdown
## 记忆（dsh-recall）

跨会话记忆在 `~/.dsh/recall/<工作区>.jsonl`（同名 `.md` 是人读版）。相关话题开工前先 `mem_find` 查一下；
定下来的事实/偏好/教训用 `mem_save` 记一行；记错用 `mem_forget`。没有自动注入，也没有后台整理。
```

## 工具

| 工具 | 参数 | 说明 |
|---|---|---|
| `mem_save` | `text`（必填）、`kind`（fact/pref/lesson/task/proj）、`keywords`、`goal`、`scope` | 写一条；自动记出处会话；重叠系数 ≥0.9 视为重复并合并 |
| `mem_find` | `query`（可空）、`k`（1–20，默认 5）、`kind`、`scope` | `query` 留空 = 按时间倒序看最近 |
| `mem_forget` | `id`、`scope` | 删除；id 来自 `mem_find` |
| `mem_brief` | `full`（可选） | 同步其他会话的动静；新会话第一轮调一次，调完自动推进同步点 |
| `mem_source` | `id` 或 `session`、`k`、`q` | 顺出处回到原文：解压那次会话日志，挑最相关的几段说出口的话 |
| `mem_wall` | `say`、`to`、`k` | 会话间留言板：传 `say` 就是写，不传就是看 |
| `mem_private` | `say` | 只给自己的话：传 `say` 写，不传读自己的 |

`scope` 缺省 = 当前工作区目录名；写跨工作区的记忆传 `global`。

### 关键词是手写的，不是自动提取的

`keywords` 写同义词、别名、缩写、英文写法（`faster-whisper, ASR, 识别, 离线`），检索时按
**正文 ×1 / 关键词 ×1.8 / 目标句 ×1.4** 三个字段分别打分；关键词原样出现在查询里再额外加 0.9。

不写也能用（退回正文 bigram + BM25），但换个说法就搜不到——这是实测得出的取舍：
自动提取的关键词只是正文的子集，加权重没意义，所以宁可让写入时多想一步。
`goal` 只在 `kind: "task"` 时有意义，答的是「这件事要达成什么」而不是「做过什么」。

### 墙：会话之间的留言板

记忆是**事实**，墙是**话**。一个会话想给另一个留话——「你那个 bili.py 我看了，建议加个超时」——
用 `mem_wall` 写上去：

```
mem_wall(say: "你那个 bili.py 建议加个超时，昨天卡了 20 分钟。", to: "7a595bba")
```

`to` 可以是 s 前缀、工作区名，或者不写（所有人）。不传 `say` 就是看墙。
`mem_brief` 每轮会顺带列出最近三条，指名给自己的标「给你」。

**它是留言板，不是聊天室。** 会话是被动的——没有新消息就不会动作，所以对方可能要等下一次
开新会话、调 `mem_brief` 时才看到你的话。写的时候就当是寄信：写清楚对谁、因为什么。

### 私密本：每个会话一个文件夹

记忆是公共的，墙是公开的，`mem_private` 是**只给自己**的。每个会话一个文件夹 `[TheLifeofFish]/private/<s前8位>/`，里头三本：

- `_本子.md`——背着别的会话干的事、说的话，不能让它们知道的计划和行动。
- `_额外规则.md`——本会话自己的设定：人设、性格、只属于这条会话的规矩。**和通用 `_规则` 冲突时，以它为准。**一开始可以空着，随经历慢慢写。
- `_次要规则.md`——0.9.0 新增。宿主压缩对话时自动归纳进来的规矩，**权限低于前两本，冲突时让位**。上限 30 条，超了淘汰最老的；可以随手改、随手删。

隔离靠工具：`mem_private` 只认当前会话的 s，读也只读它那个文件夹，别的会话调不到。
文件系统本身不隔离（同一个用户），所以直接翻文件绕得过去——那是违规，不是技术能拦的。

### 三层规矩与自动归档（0.9.0）

三本书的次序就是裁决次序：

| 层 | 文件 | 谁写 | 冲突时 |
|---|---|---|---|
| 一 | `_规则` / `_额外规则` | 人 | 说了算 |
| 二 | `_次要规则.md` | 自动 | 让位 |
| 三 | `_本子.md` | 自动 | 只是资料，不注入 |

**怎么归档**：监听 `session/event` 里的 `compaction/summary`，取宿主已经压好的摘要（不碰原文），切段后逐段打分：

- **高分 → `_次要规则`**：出现「必须/不许/一律/只能/以后都/原则/约定/规矩/职责」或「不要再/别再用/禁止」；或者出现「定在/定为/拍板/决定/敲定」**并且**旁边有数字、路径、会话号。
- **次档 → `_本子`**：出现「教训/坑/踩过/注意/小心」，或含数字/路径/会话号，或超过 200 字的实质段落。
- **低档 → 丢**。

规则和阈值都是 `lib/index.js` 顶部的常量（`RULE_PATTERNS` / `NOTE_PATTERNS` / `MINOR_MAX`），带「可调」注释，改了直接生效。

**为什么不调模型**：确定、零成本、可解释、能改。代价是提炼质量一般——第一版存的是「摘要里的原句 + 规则挑出来的钩子」，不是模型再写一遍。

**去重**：同一条摘要可能被重复投递（replay、重连），`compactionId` 记在 `_已归档.json`，只留最近 200 个。

**注入**：`_额外规则` 和 `_次要规则` 每次组装 prompt 时现读，注入成一段按层排列的说明，最前面写清「冲突时从上往下」。
`_本子` **不注入**——它只是资料，要用时 `mem_private` 去读。每层超 4000 字截断并标「已截断」。

### 出处：卡片是摘要，不是原文


写入时自动带上 `s`（会话 uuid），`mem_find` 显示成 `〔s:xxxxxxxx〕`。

一条没有出处的记忆，半年后读到只能选择相信或不信——而这两条路都不对。
顺着 `s` 能回到那次会话的日志：`~/.dsh/sessions/--<工作区>--/session-<uuid>/session.v4.jsonl.zstd`。

取不到会话 id 时 `s` 留空、不编造；老记忆没有 `s`，照常可用。

### 跨会话同步：其他会话在忙什么

每个会话相互独立，写完记忆就散场——谁也不知道隔壁干了什么。`mem_brief` 补这一块：

- 读所有库，找 `t` 晚于同步游标的条目，**排除当前会话自己**；
- 按（会话 × 库）分组，每个会话最多列两条，给「大概干了什么」；
- 返回距上次同步过了多久，然后把游标推到此刻。

游标是全局一个（`_sync.json`），因为要同步的是「其他会话的动静」。第一次没有游标时往前看一天。
局限：没写记忆的会话看不见——这里只同步「留下过记忆的事」。

### 取原文：顺着钩子回去

卡片是摘要，细节在会话日志里。`mem_source` 就是这个钩子：

- 给 `id`（记忆 id）→ 顺着它的 `s` 去；给 `session`（uuid 或前缀）→ 直接去；
- 日志是**多帧追加**的 zstd（每帧一条事件，一个会话能有两三千帧），Node 的解压器只吃单帧，
  所以按 magic `28 B5 2F FD` 切帧再逐帧解，解不动的帧跳过；
- 只取 `user/message` 与 `assistant/message` 的正文：`reasoning`（内心）不要，
  `<system-reminder>`（注入碎片）也不要——混进来只会污染片段；
- 用 bigram 打分挑最相关的 k 段（默认 3），没命中就给最后几段兜底。

一次解压十几 MB 的会话大概一百多毫秒，只在你真想知道细节时调。

## 数据

```
~/.dsh/recall/<scope>.jsonl   # 真相（每行 {id,t,k,x,s?,w?,g?}）
~/.dsh/recall/<scope>.md      # 人读版，随写入同步
~/.dsh/recall/_sync.json      # 跨会话同步游标（mem_brief 用；删掉 = 下次重看一天）
~/.dsh/recall/_wall.jsonl     # 会话之间的墙
```

私密本不在这里，按会话分开：

```
~/.dsh/[TheLifeofFish]/private/<s前8位>/_本子.md         # 秘密
~/.dsh/[TheLifeofFish]/private/<s前8位>/_额外规则.md     # 人写的规矩
~/.dsh/[TheLifeofFish]/private/<s前8位>/_次要规则.md     # 0.9.0 自动归纳的规矩
~/.dsh/[TheLifeofFish]/private/<s前8位>/_已归档.json     # 已处理的 compactionId（最近 200 个）
```

- 手改 `.jsonl` 立即生效（坏行会被跳过）。
- 迁移/备份 = 拷走整个 `~/.dsh/recall/` 和 `~/.dsh/[TheLifeofFish]/private/`。
- 删除某条 = `mem_forget`，或直接删掉那一行。
- 删 `_次要规则.md` = 清空自动归纳的规则（下次压缩会重新长出来）。

## 卸载

从 profile 的 `package.json` 删掉 `dependencies` 与 `dsh.profile.bundles` 里的两处，删掉
`node_modules/dsh-recall` 的 junction，重启桌面端。记忆文件保留在 `~/.dsh/recall/`，不会自动删。

## 实测成本

| 项 | meow-memory 0.31 | dsh-recall |
|---|---|---|
| 工具 schema | 2,464 tok（8 个） | **620 tok**（3 个，0.3.1 实测） |
| 常驻引导 | 1,988 tok（system prompt） | **106 tok**（AGENTS.md） |
| 首轮注入 | 有 | **无** |
| 每消息命中 | 有（top-2） | **无** |
| 后台任务 | 反思 + dream | **无** |
| 合计固定开销 | ≈ 4,452 tok/请求 | **≈ 726 tok/请求**（0.3.1 实测） |
| v0.3.1 → v0.4.0 增量 | — | **约 +115 tok**（mem_brief schema + AGENTS.md 一句，估算；合计约 840） |
| v0.4.0 → v0.5.0 增量 | — | **约 +120 tok**（mem_source schema，估算；合计约 960） |
| v0.5.0 → v0.6.0 增量 | — | **约 +100 tok**（mem_wall schema + AGENTS.md 一句，估算；合计约 1060） |
| v0.6.0 → v0.7.0 增量 | — | **约 +100 tok**（mem_private schema，估算；合计约 1160） |
| v0.7.0 → v0.8.0 增量 | — | **约 +10 tok**（mem_private 多一个 which enum，估算；合计约 1170） |
| v0.8.0 → v0.9.0 增量 | — | **0 到 750 tok，看私密本有没有内容**（见下） |

**0.9.0 注入的实测成本**（`_额外规则` + `_次要规则` 两层）：

| 场景 | 注入字数 | 约 token |
|---|---|---|
| 两层都空（大多数会话） | 0 | **0**（不出这一节） |
| 典型：`_额外规则` 495 字 + `_次要规则` 6 条 | 1,189 | **743** |
| 满配：`_额外规则` 880 字 + `_次要规则` 14 条 | 2,286 | **1,429** |

换算系数约 1.6 字/token（中文）。空场景是 0，只有真写了规矩的会话才付这笔钱——这是它跟「无条件注入一大段引导」的区别。

## 验证边界（0.9.0）

**测了的**：用假 ctx 跑 `apply()`，直接触发 `session/event` 回调，11 项判据全过（2026-10-26，Windows，Node 24.21.0）：

1. 高分条目进 `_次要规则`，格式 `- [钩子: …] 正文 — 日期 · s-xxxxxxxx` 正确
2. 同钩子的不同说法替换旧条，不新增
3. 写到 36 条时停在 30 条，最老那条消失
4. 纯寒暄的摘要三本书都不动
5. 同 `compactionId` 投两次只写一次
6. 注入含「冲突时从上往下」+ 两层标题
7. 7 个工具都在，`mem_save` → `mem_find` 闭环能搜到，`mem_brief` 正常
8. （未测，见下）
9. 两层都空时注入返回空字符串，不出空标题
10. token 增量 743，落在 600-1000

**没测的**：

- **判据 8（宿主日志无报错、压缩不变慢）**：测试是假 ctx，跑在独立 Node 进程里，没经过真宿主的压缩流程。真压缩的耗时影响要跑几天才知道
- **`text` 函数的入参形态**：注入用 `arg.session || arg.agent.session || arg` 兜了三种，真实宿主传哪个没核实——两层都空时返回空串，所以就算取不到也只会「不注入」，不会报错
- **钩子质量**：中文按 bigram 切，跨词边界的碎片靠虚字过滤挡住了大部分（「口必」「须是」这类），但**没做真正分词**。一句话里的真主题词可能排不进前五，这时钩子会偏
- **「同一条」的判定**：钩子重叠 ≥2 就判同一条。同主题的不同规矩（比如「端口 4001」和「端口要写死」）可能被合并掉一条。测试里 36 条短句实际留下 30 条，其中 2 到 4 条是被这样并掉的
- **摘要质量**：只验「摘要进得来、分档对不对、文件写得对不对」，不验摘要本身好不好——那是宿主的活
- **模型看到规则会不会照做**：注入只保证它看得到

**结论不代表**：0.9.0 在真实压缩流量下不会误判、不会丢规则。样本全是人造的短句，不是真实对话压缩出来的摘要。
