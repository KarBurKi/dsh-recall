### 3.3 `E8`：ZWJ 家庭 emoji 被切在连接处，留下悬挂 U+200D

**位置**：`lib/index.js` 的 `flatSpan()`，第 1043–1047 行：

```js
const chars = Array.from(raw.replace(/\s+/g, " ").trim()); // 按码点拆
...
const keep = Math.max(0, max - Array.from(mark).length);
return chars.slice(0, keep).join("") + mark;
```

`Array.from` 按**码点**拆，不按**字素簇**拆。`👨‍👩‍👧` 是 5 个码点（男人 + ZWJ + 女人 + ZWJ + 女孩）；截断点正好落在第一个 ZWJ 之后时，正文留下「男人 + ZWJ」，ZWJ 后面直接接省略号。

**期望**：截断时不要把 ZWJ 序列切在连接处；至少不要把悬挂的 U+200D 留在正文末尾。没有 U+FFFD 是必要条件，不是充分条件。

**实际**：正文尾部码点序列是 `U+1F468`（👨）+ `U+200D`（ZWJ）+ `U+2026`（…）；完整家庭 emoji 没有保留；文件里没有 U+FFFD，也没有孤立代理对。

**输入构造**：

```js
const text = "必须" + "A".repeat(1184) + "👨‍👩‍👧" + "尾".repeat(10);
```

`text.length` 是 1204；`flatSpan(...,1200)` 截到 1200 字，标记「原文 1204 字」。

**证据**：`artifacts-v2-c0ffee11/E8-zwj/_压缩存档.md`，第 14 行尾部：

```text
...AAAA👨‍…（原文 1204 字）
```

用码点检查：

```text
index 1436
sliceJSON "AAAAAAAAAA👨‍…（原文 1204 字"
codepoints U+41 U+1F468 U+200D U+2026 U+FF08
```

这条是额外发现，不在题面 9 条里；README 已承认「组合字符、ZWJ emoji 可能被 Array.from 切在连接处，只验证了单个 emoji 的代理对不会被切坏」。本轮确认这个边界仍能构造出坏状态。

## 5. 没验成 / 不能下结论的

1. **旧档真断号（§1 → §3）**：旧格式没有围栏时，§1 后直接 §3 与「伪节 §3」在文本上不可区分；插件选择「断号即伪节」，所以无法构造一个既真实断号、又能被判定为「真旧档」的输入。这条没有判据。
2. **更复杂的字素**：只测了家庭 ZWJ（👨‍👩‍👧）、单个 emoji 代理对；肤色修饰符、旗帜（区域指示符对）、组合音标、阿拉伯/印度组合字符都没测。
3. **I/O 失败**：`archiveCompaction()` 先写 `_已归档.json` 再写正文；如果正文写失败，id 已经记下，重放会被跳过，可能永久丢。没有做写失败注入（Windows 上没改权限/没塞只读文件），未验。
4. **200KB 体积淘汰**：最大只写到 67KB（50×1200 的 60000 预算用例），没有构造超过 200KB、触发 `trimArchive` 删旧节的真实样本；淘汰时的钩子行同步、`trimmed` 计数未验。
5. **并发写入**：单进程、单 handler、串行调用；两个会话/两次写入同时读改写同一文件没测。
6. **真实摘要样本**：全部是自造输入，没有读本机真实会话摘要；真实分布下的段长、语言比例、钩子密度未验证。
7. **204800 字节整的边界**：只测了 204801（拒写）和正常小条目；正好 204800 是否可写没单独测。
8. **旧档头部的自定义行**：没有测旧档头部有非标准说明行时，重写是否丢行；本轮只测了标准头。
9. **非 Windows 平台**：只在 Windows 10.0.26200 x64、Node v24.21.0 上跑；Linux/macOS 的路径、换行、文件系统行为未验。
10. **作者测试/上一轮报告**：没有采信其中任何断言；只把 `fix-097b.mjs` 的 harness 形状当作驱动样例，所有结论来自本轮脚本。
