### 3.3 五条假 PASS 的证据

**4.1（作者 196-198 行）——量错了对象。**
夹具：`mem_private({which:"minor", say:"必须" + "字"×598 + "，端口 4001。"})`。落盘那行是：

```
- [钩子: 字字,4001,端口] 必须字字…（原文 609 字） — 2026-10-26 · s-f00d0b02 · hits=0
```

整行 294 字，正文（`] ` 到 ` — ` 之间）**240** 字。作者用 `line.lastIndexOf(" — ")` 取分隔符，`slice(k+3)` 拿到的是 `2026-10-26 · s-f00d0b02 · hits=0`，**32** 字——那是日期/会话号/hits 的尾巴，不是正文。`32 <= 240` 永远成立。我伪造了一条正文 3000 字、尾巴不变的行，套作者公式还是 32、还是 PASS（`v4-probe.mjs` 输出）。注释（195 行）说「240 是正文上限，整行还带 `- ` 和钩子标记那些结构字符」——想法对，但 ` — ` 在正文**尾部**，不在正文前面。结论：这条抓不到「240 上限被撑爆」，正文真涨到 1000 字它照样绿。

**4.2（作者 202-204 行）——输入没落到切点上。**
夹具 `"必须" + "A"×1197 + "😀" + "尾"×10`：码点共 1210，标记 12 码点，`keep = 1200-12 = 1188`；emoji 在码点 **1199**，离切点还有 11 个码点，整颗被丢掉。所以旧代码（`s.slice(0,1188)`，按 UTF-16 切）和新代码（`Array.from` + 后退）产出的正文**逐字节相同**：`AAAA…（原文 1211 字）`。我按两种实现各跑了一遍（`v4-probe2.mjs`）：`旧096同新: true`。把 emoji 挪到码点 1187（`"必须" + "A"×1185 + "😀" + "尾"×20`），旧代码才会留一个孤立高代理、落盘变 U+FFFD，新代码保住整颗 emoji——这时作者这条断言才分得开新旧。当前夹具分不开。

**E8 / E8-b（作者 265-268 行）——同一个毛病。**
`"必须 D:/logs 端口 4001 "`（19 字）+ `A`×1180 + `👨‍👩‍👧` + `尾`×20：家 emoji 的第一个码点在 **1199**，切点 1188，整组被丢，输出里连一个 U+200D 都没有——`/\u200d(?!\p{Emoji})/u` 和 `includes("\u200d…")` 都恒为假。E8-b 是同一份空转夹具上的第二条断言。把家 emoji 挪到码点 1184（`A`×1165 起步），旧代码切完正文以「👨 ZWJ 👩 ZWJ」结尾，E8 的断言就会响（`E8可见悬挂ZWJ: true`），新代码会退到 A 后面。现在这组夹具两种代码输出一样（`旧097同新: true`），等于没测。

**1x-b（作者 245 行）——恒真式。**
`!inFence(out,"## §999 伪节") || out.indexOf("## §999") > out.indexOf("## §1")`。第二项：§999 在 §1 的正文里，位置必然在 `## §1` 之后，**永真**；整个 OR 于是永真。我拿三种输出试：正常（围栏内）、模拟 bug（§999 被升格成真节、在围栏外）、§999 字符串完全不存在——三种都 PASS（`v4-probe.mjs`）。而且第一项和描述是反的：描述说「在围栏外等于 false」，代码写的是 `!inFence`（不在围栏里）——就算没有 OR，它测的也是相反的命题。这条唯一的实际价值被 1x 占了：1x 的 `nums.join(",")==="1,2"` 在伪节升格时会变成 `1,999,2`，真能拦住。

## 4. 解析器自证

**我的解析器**：`v4-run.mjs` 里的 `scanLines`/`parseArchive` 先用插件自己写出来的已知正确档喂一遍（P1：2 节 2 行、正文都在围栏内），再用迁移后的三节档（P2：围栏里的伪节不算节），再做两条负控制——删掉 §1 钩子行要能报出「1 行 vs 2 节」（P3），围栏外插一行完整形状的伪节要能数出 3 节（P4）；另外验了未闭合围栏不算围栏（P5）和 `| 钩子 | §1 |` 当数据行保留（P6）。六条全 PASS 之后，我才用它读作者的文件。作者 4.1 的 `len`、1x-b 的 `inFence` 我都是单独抽出来、用三种输出对照着重算的，没有直接信他们的 helper。

**作者解析器**（第二步审的，四处）：

1. `sections()`（44-59 行）只按 `\n` 切，且只认反引号围栏。插件自己写出的档是 LF + 反引号，所以对插件输出没问题；但旧档里如果有 CR-only 或 U+2028 行终止符（`scanLines` 认四种，index.js:476-511），它会漏节。31 条夹具都是 LF，没触发。
2. `inFence()`（62-73 行）遇到含 needle 的围栏行会先翻转 `fence` 再返回，语义上把「开围栏那一行」算成围栏内；插件不会把 needle 写在围栏行上，这次没影响。
3. 钩子行读取器不跳围栏（上面 3.4 最后一段，有实测）。
4. 4.1 的 `slice(k+3)` 和 1x-b 的 OR 是两处实打实的写错（见 3.3）。
