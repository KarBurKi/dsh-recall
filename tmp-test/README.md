# tmp-test：测试脚本怎么读

这个目录里不是同一类东西，读之前先分清。目录名带 `tmp-` 是历史原因，它现在入库了。

## 主测试套（要维护）

跑这五个，就是 README 上说的「94 条」：

```
node tmp-test/criteria-091.mjs   # 10 条
node tmp-test/fix-092.mjs        # 11 条
node tmp-test/fix-093.mjs        # 16 条
node tmp-test/fix-097.mjs        # 25 条
node tmp-test/fix-097b.mjs       # 32 条
```

`fix-097` 是指挥中心那三条判据，`fix-097b` 是四轮独立复验挖出来的洞。
两条共用一个 `judge()` 风格，输出末行 `=== 通过 N/M`。

**改行为就要改这里**，不成立就有回归。

## 旧实现证据（要维护，数量不多）

`old-*.mjs` 不是历史代码的归档，是**用来证明「改过的断言在旧实现上会红」**的对照物：

| 文件 | 是什么 |
|---|---|
| `old-0.9.6.mjs` | `git show 5924aea:lib/index.js`，0.9.7 全部改动之前 |
| `old-2db1321.mjs` | `git show 2db1321:lib/index.js`，0.9.7 主体已上、切点未修 |
| `old-slice.mjs` | **造的**，把当前 `flatSpan` 的切点回退换回 `slice(0, keep)` |

用法：`FIX_SRC=$PWD/tmp-test/old-0.9.6.mjs node tmp-test/fix-097b.mjs`

`old-impl-red.md` 是这四个实现（含当前）的实测结果。

**这几个文件别随手删。** 没有它们，「这条断言能抓到东西」就只是句话。

## 复验脚本（一次性，不维护）

`verify-0.9.7-ba53cbe7.mjs`、`v2-c0ffee11.mjs`、`v3-beefcafe.mjs`、`v4-run.mjs` ——
四轮独立复验方自己写的断言套。**保留是为了留证**：它们记录了每一轮「复验方自己认为什么是坏状态」，
换个验证者会写出不一样的东西，这本身就是信息。

**不要跟着插件演进改它们。** 它们验的是当时那个版本，改了就变成作者的用例了。

## 验收探针（一次性，不维护）

`probe-*.mjs` 是第五方验收（测试中心 `bdda57e2`）在核 0.10.0 收尾那三件时用的探针——
验 `FIX_SRC` 机制真生效、验 `old-slice` 造得对、验 README 描述和实际一致。

**不随插件演进，不是插件自带资产。** 后来人看到它们红了不用修，那不是回归，是那个探针过期了。
证据在 `【文档区】\测试文档\验收报告-recall0.10.0收尾-bdda57e2-20261026.md`。

## 报告

`v2-c0ffee11-report.md`、`v4-expected.md`、`v4-report.md`、`old-impl-red.md` ——
复验方和作者留下的判断记录。`v4-expected.md` 尤其值得读：那是**先于作者用例**写的期望值表，
从头读一遍能看出「独立给期望」和「看着代码写断言」差在哪。

## 一条规矩

这个目录里的数字要能被读者自己跑出来。写「94 条全绿」就得说清是哪五个脚本、怎么跑；
写「21/32 红」就得说清用哪个 `FIX_SRC`、跑哪个脚本。

**凡是写进文件给人看的数，必须能被读者用文件里的内容自己验出来。**
